**RingForge Workbench v1.12.0 — "Standalone"**

The first release you can download and run. No Python, no virtual environment,
no checkout: unzip and go. Static triage works immediately; a full detonation
needs a VM and a few tools that cannot legally be redistributed.

```powershell
Get-FileHash .\RingForge-v1.12.0-win64.zip -Algorithm SHA256
```

Compare the result against the `.sha256` asset published beside the zip.

**The binary is unsigned**, so this hash is the only integrity check available.
SmartScreen will warn on first run, and antivirus may object — a tool that
bundles YARA and inspects malware trips heuristics. Verify the hash, then
**More info → Run anyway**.

Unzip somewhere writable. **Not `C:\Program Files\`** — cases, logs and
`config.json` are written beside the executable.

## What is in the box

- `ringforge-gui.exe` — the workbench window
- `ringforge.exe` — the command line (`scan`, `combine`, `export`)
- **capa 9.4.0** and **FLOSS 3.1.1**, both Apache-2.0, with their licence text.
  `tools\VENDORED.txt` records the upstream version and SHA256 of each
- `README.md` (user guide), `INSTALL.md`, `TOOL_SETUP.md`
- `licenses\` — licence text for every library inside the bundle

Procmon, Autorunsc, Sysmon, ProcDump and Npcap are **not** included and cannot
be: the Sysinternals EULA prohibits redistribution and Npcap is proprietary.
`TOOL_SETUP.md` covers installing them, with the exact filenames the engine
looks for.

## New in this release

**It is installable.** `pip install` works, the dependency set is declared
rather than frozen, and optional collectors are extras so a missing one stays a
reportable coverage gap rather than an import error.

**There is a command line.** `ringforge combine | scan | export`. `--json`
owns stdout and everything human goes to stderr, so piping into `jq` or
`ConvertFrom-Json` works. `--fail-on BAND` exits non-zero at or above a band so
a pipeline can gate on it.

**A verdict says what produced it.** At `schema_version` 1.0 every verdict
carries the analyzer version, the commit, library versions and what the YARA
scan actually compiled. `rules_compiled` is the field that matters:
`rule_file_count` counts files on disk and says nothing about whether any
loaded, which is how a rule set that never compiled read as a clean scan for a
fortnight.

**Verdicts export as OCSF Detection Findings.** `ringforge export` writes
NDJSON for a forwarder to ship, and nothing opens a socket. The mapping carries
**coverage**: `Unknown` maps to OCSF severity 0 and never to Informational, so a
detection rule can alert on Corroborated and separately on Unknown-where-
coverage-was-incomplete.

**A standalone build.** One directory, two executables, the version and commit
stamped in — a frozen build has neither git history nor package metadata, and a
verdict nobody can trace to a build is not much of a verdict.

## Fixes

- **The windowed build flashed a command prompt every four seconds.** The
  containment watch shells out on a timer, and a PyInstaller GUI has no console
  to inherit, so Windows gave every child its own window. All 38 subprocess
  call sites now suppress it.
- **capa never ran unless you had also installed `capa-rules`.** The standalone
  build embeds its own rules; a missing rules directory is now recorded rather
  than treated as "capa did not run". capa was also the only tool resolved
  purely from `PATH`, so a bundled copy was invisible to it.
- **`--json` did not own stdout** for any sample with subfiles to triage —
  three progress markers were printed there. They go to stderr now.
- **An empty case directory reported the cleanest band the model has.** The
  guard covered a run whose collectors all *failed* and missed the run that
  never *happened*.
- Data files the package ships — the logo, Procmon filter configs, this
  project's own YARA rules — reached no installed copy at all. They are package
  data now.

## Upgrading from v1.11.x

- **Module paths moved.** Five pipeline modules left `scripts/` for
  `static_triage_engine/`, and the authored YARA rules moved into the package.
  `scripts/` keeps import aliases, so code is unaffected — but
  `bootstrap_yara_rules.ps1` reads the rules from their new home, so pull before
  running it.
- **Static scores may change.** capa now runs for anyone who has capa without
  `capa-rules`, where it previously did not run at all. More capabilities
  detected means some samples band higher than they did.
- `case_dir` is gone from the verdict envelope. It was an absolute path that
  identified the analyst's machine and was read by nothing.

## Known limitations

- **Windows only.** The engine shells out to Procmon and reads `ctypes.windll`.
- **Unsigned.** SmartScreen and AV will object. Verify the SHA256.
- **Dynamic analysis is not sandboxed.** It runs the sample for real. Use a VM
  you can revert, take a snapshot, and verify containment first.
- The bands have never been measured against a labelled corpus. Per-category
  benign rates exist and are cited in the code; an end-to-end confusion matrix
  does not yet.
